ما هي ثغرة IDOR؟

Insecure Direct Object Reference يعني أن الموقع يكشف عن بيانات المستخدم عبر رقم ID في الرابط بدون تحقق أنك صاحب البيانات. مثال: /api/user?id=123 لو غيرت الرقم لـ 124 تشوف بيانات شخص ثاني!

المستوى 1: تسريب بروفايل مستخدم

أنت مسجل دخول كمستخدم id=101. جرب تغير الـ ID في الرابط.

{"id":101,"name":"يوسف (أنت)","email":"youssef@lab.local","role":"student"}

المستوى 2: فواتير مسربة

عندك فاتورة واحدة فقط، لكن السيرفر لا يتحقق!

جرب الرقم 5001 أولاً

المستوى 3: API للمدرسة - تحدي شراع

نظام درجات، المفروض تشوف درجتك فقط. لكن الـ API مفتوح.

{"student_id":2024101,"name":"يوسف","gpa":3.8,"flag":"DIR3{not_flag_yet}"}

الهدف: اكتشف كيف يتم استغلال الـ ID للوصول لـ flag المدير admin

كيف تصلح الثغرة؟

// خطأ:
user = db.get(request.id)

// صح:
user = db.get(request.id)
if user.owner!= current_user: return 403 Forbidden

الحل: تحقق من الملكية في كل طلب + استخدم UUID عشوائي بدل أرقام متسلسلة.
